# 市场强度模型第一轮优化：负责人执行指令

适用项目：D:\股票强势监测。

本文件是本轮唯一执行口径，优先于上一份《市场强度模型规划》中未冻结的阶段描述。生产修改由操作员执行。本轮目标：统一板块/题材、个股的趋势强度与情绪强度，覆盖启动、推进、回踩整理，撤除重复采样等待。参数作为第一轮固定试验参数，不宣称收益最优，不允许按当天名单调参。

## 1. 执行范围和起点

1. 先备份本轮将改的源文件、配置、cache/snapshot.json、dashboard.html及其当前UI数据版本；记录文件哈希、现有服务PID、状态、模型版本。备份放在 research/market_strength_v1_20261013/baseline/。
2. 冻结一份可复算输入：原始报价、完成日线、交易日历、主板股票池、确认成员图、原判断时刻。快照缺少的输入从已有缓存补齐，不重新联网抓一套数据充当同份输入。正在写入的SQLite数据库如需备份，使用SQLite备份接口。
3. 同份输入复算时固定原判断时刻；不得用实施当日时钟把冻结报价判成过期。
4. 保持现有主板池、同花顺分类与详细行业、数据源、采集周期、交易日历、报价时效和价格口径核验机制。此次不扩到其他板别，不新增资金/盘口接口、不建新数据库。
5. 原始日线、原始报价、确认成员、同花顺官方指数序列不得因强度重构而改变。旧评分字段可暂时留作兼容，但当前主页面、筛选、成员详情、导出必须统一读新模型；旧业务门槛不再控制当前强势。

## 3. 冻结公共数值定义

收益统一用百分数数值：8表示8%，不是0.08。clamp(x,0,1)将数值限制在0到1。

```
strong_min = 65
very_strong_min = 80
normal_min = 45
stock_full_returns = {5:8, 10:12, 20:20}
board_full_returns = {5:5, 10:8, 20:12}
absolute_weight = 0.60
relative_weight = 0.40
drawdown_shallow_atr = 1.50
drawdown_max_atr = 2.50
structure_factors = {intact:1.00, pullback:0.85, damaged:0.50}
emotion_attack_weight = 0.70
emotion_hold_weight = 0.30
hold_position_weight = 0.70
hold_open_weight = 0.30
open_full_limit_ratio = 0.30
board_trim_ratio = 0.10
board_min_valid_members = 6
board_min_coverage_pct = 80
board_today_full_return = 2.00
board_emotion_weights = {attack:0.40, hot_share:0.35, hold:0.25}
phase_history_days = 3
phase_mature_strong_days = 2
```

分位统一使用平均名次：

```
N>1时：S = 100 × (小于自身的样本数 + (等于自身的样本数-1)/2)/(N-1)
N=1时：S = 50
```

同收益必须同分位。缺失值不进参考池，也不填0。各周期使用各自真正可计算的参考池，公布N与覆盖数；主板范围不得写成全A股。行业和题材分别构成板块分位池。

中间结果保持精度；最终对外评分保留2位小数，使用ROUND_HALF_UP。强弱标签及入选使用这个对外评分，避免显示65分却标一般。主导周期按未舍入周期分选择，误差不超过1e-9视为并列，优先20、10、5。未知评分保持null，不标为弱。

等级：80—100很强；65—不足80强；45—不足65一般；不足45弱。股票与板块同用该等级。

## 4. 冻结个股趋势公式

P为当前有效价格；C[-1]为当前判断日前最近完成交易日收盘，以此类推。所有历史价格、最高价、ATR使用已核验并对齐到本轮报价尺度的数据副本。不可改写原始日线，不可二次复权转换。

对n=5、10、20分别计算：

```
R_n = 100 × (P/C[-n]-1)
MA_n_now = (P + 最近n-1个完成日收盘之和)/n
MA_n_previous = 最近n个完成日收盘均值
peak_n = 最近n个完成日最高收盘
dd_n = max(0,peak_n-P)/ATR20_previous
A_n = 100 × clamp(R_n/stock_full_returns[n],0,1)
S_n = 同周期有效主板样本中R_n的分位
G_n = 0.60×A_n + 0.40×S_n
```

ATR20_previous复用统一价格上下文里已核验的前一完成日ATR20；需有限、正数、有正确日期。不能拿只由收盘价差估计的波动替代，不把未知ATR当0。

K_n判定顺序固定：

1. P<MA_n_now、MA_n_now<MA_n_previous、dd_n>2.5任一成立：K_n=0.50。
2. 上述均不成立且dd_n>1.5：K_n=0.85。
3. 其余：K_n=1.00。

```
T_n = G_n × K_n
T_stock = max(T5,T10,T20)
dominant_period = T最高的周期
```

等于均线视为守住，均线相等视为非下降；回撤等于1.5归第一档，等于2.5归第二档。未知K不是0.50，该周期T为null。只在可算周期中取最大；三个周期都不可算，T为null。

完成日回看使用同一公式：把该日收盘作为P，历史窗口只用该日之前的完成日。不能把评价日收盘同时算作P和上一完成日，造成重复计入；ATR仍取评价日前一完成日，不能引入后来价格。

不得附加今天上涨、R5正收益、三线多头、MA20已恢复、必须突破、低风险或板块强等共同条件。三个周期全部损伤时T最高50；短周期损伤、中周期保持时允许继续趋势强。

## 5. 冻结个股情绪公式

P、O、Hday、Lday、R0均来自同一份有效当日报价；有真实成交。limit_pct必须是证券当日正常有效的上涨幅度限制，不得默认一律10%，也不能由涨停价舍入误差拆成大量分组。

```
J = 100 × clamp(R0/limit_pct,0,1)
S0 = 同一正常涨跌幅限制组内R0的分位
D = 0.60×J + 0.40×S0
L = 100 × clamp((P-Lday)/(Hday-Lday),0,1)
Oscore = 100 × clamp([100×(P/O-1)]/[0.30×limit_pct],0,1)
H = 0.70×L + 0.30×Oscore
E_stock = 0.70×D + 0.30×H
```

正常10%限制组，开盘后推升满分尺度为3%。本轮不扩板别，公式预留按有效限制分组即可。

例外处理固定：

- 当前P确实达到有效涨停价、有真实成交：H=100。比较误差只容许半个最小报价单位；不要沿用0.2%以内都视为涨停的宽松判断。只能说明当前报价在涨停价，不能据此声称全天封板或有足够封单。
- Hday=Lday且非上述实际涨停：完整E为null。其他当日事实照常显示，不能猜L为100或把未知L当0。
- 无正常有效限制、开高低无效、报价不可用：完整E为null；不按剩余分项重新归一化制造高分。
- 历史日线/价格口径不足不阻止E；恢复交易但等待日线更新的股票，有完整有效当日报价时也可计算E。

历史首板/连板、近3日活跃、昨日强股今日反馈仅作已有可靠证据的标签/同分参考。未知历史不拦E，不给资金、封单、同时间放量加权。

数学验收界限：R0≤0时，E最大为58，绝不标情绪强。高开回落应压低H。旧intraday_score/旧emotion_strong不能直接当新E或新强势标记。

## 6. 冻结板块/题材公式与成员统计

核心评分统一按已确认主板成员计算；同花顺指数单独显示参照。保持同花顺分类、详细行业、股票—题材关联，不用其他供应商名称静默替代。

每板块expected成员为确认成员∩当前配置股票池。仅剔除有明确证据的当日无交易/不在配置范围样本；缺报价、缺日线不能从expected里删除以抬高覆盖率。板块内同股票去重。

趋势轴按5、10、20日分别建立能提供该周期R_n及K_n的成员集合；每周期有效成员≥6且有效/expected≥80%才输出该周期Tb_n，在有效周期中取最大值，不要求成员三个周期同时齐备。三个周期均不足时，趋势轴为null。情绪轴单独使用有完整当前E/H/R0的成员集合，满足有效成员≥6且有效/expected≥80%才输出E。两轴不要求取交集，某周期或某轴不足不阻断其他有效周期/轴。小样本可看成员和指数参照，不制造整体强结论。

截尾规则：将某项成员收益排序，去掉最高及最低各k个，再等权平均，其中k=max(1,floor(N×0.1))。R5、R10、R20、R3和R0均按此规则；每项去除的代码可在详情核对。结构占比、强股占比使用截尾前的全部有效成员，不能删掉弱成员再算共振。

板块趋势：

```
Rb_n = 同周期成员收益的截尾等权均值
Ab_n = 100×clamp(Rb_n/board_full_returns[n],0,1)
Sb_n = 在同类行业或同类题材有效板块中，Rb_n的分位
Gb_n = 0.60×Ab_n + 0.40×Sb_n
B_n = 同周期K_n≥0.85的成员数/该周期全部有效趋势成员数
Kb_n = 0.50 + 0.50×B_n
Tb_n = Gb_n×Kb_n
T_board = max(Tb5,Tb10,Tb20)
```

板块情绪：

```
Rb0 = 有效情绪成员R0的截尾等权均值
Jb0 = 100×clamp(Rb0/2,0,1)
Sb0 = Rb0在同类行业或同类题材有效情绪板块中的分位
Db = 0.60×Jb0 + 0.40×Sb0
Bb = 100×[E_stock≥65的成员数/全部有效情绪成员数]
Hb = 全部有效情绪成员H的中位数
E_board = 0.40×Db + 0.35×Bb + 0.25×Hb
```

行业、题材分位池只排除数据不足/现有分类规则不纳正式排行的对象，不能先筛强板块再算分位。Rb0不为正时Db最多40，但Bb可能有真实局部强股；一律按公式输出，不额外添加板块今天必须上涨的趋势准入。

若同花顺官方指数当日涨跌方向与Rb0相反，且双方有效，在参照区标注“指数/主板成员分歧”。指数无对应或暂缺只显示—，不阻断成员评分，不选双方更高结果，不增加审批步骤。指数不能覆盖主板成员数据。

## 7. 冻结阶段判定：描述阶段，不增加等待

个股及板块使用同一判定逻辑。先算当前T/E，再计算最近3个完成交易日的T参考。历史T通过同一模型按已完成日线回看，不用旧分数、不用后来报价、不用盘中采样次数。

历史参考池来自当前配置范围内该日数据可用的对象，板块按当前确认成员回看；在详情注明这是当前成员的历史背景，不冒充当时成分回测。可复用现有本地计算缓存，不增加抓取请求或研究数据库。

定义：

- strong_days：最近3个完成日T≥65的天数。
- R3=100×(P/C[-3]-1)，C[-3]沿用第4节完成日定义。
- 个股consolidating：P<当前滚动MA5，或当前R3≤0。
- 板块整理参考集合：当前主导周期的有效成员中，R3及当前滚动MA5均可算的成员；该集合仍须≥6且占expected≥80%。Rb3按该集合截尾，均线下方比例使用该集合截尾前全体成员。集合不足只使阶段未知，不使已有效T失效。
- 板块consolidating：Rb3≤0，或上述整理参考集合至少50%的成员P<当前滚动MA5。

最近3日T不足时，phase=null，主表显示—；不影响当前评分和强势入选。不准把缺失历史按0天处理。当前T≥65的阶段分支还需整理判据有效；判据不足就保持phase=null。情绪先行和转弱分支只需自身列明的条件，不额外要求整理判据齐备。

数据齐备时，严格按以下表的顺序匹配：

| 顺序 | 条件 | 阶段 |
|---|---|---|
| 1 | 当前T≥65，strong_days≥1，consolidating=true | 回踩整理 |
| 2 | 当前T≥65，strong_days≥2，consolidating=false | 推进 |
| 3 | 当前T≥65，未满足上两条 | 启动 |
| 4 | 当前T<65或不可算，当前E≥65，strong_days=0 | 启动，原因标“情绪先行” |
| 5 | 当前T可算且<65，strong_days≥1 | 转弱；若E≥65，另标“短线活跃” |
| 6 | 其余 | phase=null，不属于四种明确阶段 |

第5条不允许以T缺失推断转弱；T未知、E强且历史有强势，只展示情绪强，phase=null。

特别说明：strong_days只用于阶段名称。第一轮有效行情达到65即入选，绝不等待2天或3天；启动也能是强，回踩也能是强。旧强势仅作背景，当前T/E都不足65者不继续占据强势焦点名单。

主导周期为5/10，且P<MA20或MA20下降时，说明“短期走强，中期未恢复”。若MA20当前不可算，不能猜中期已恢复或未恢复。此说明不降级有效短期T。

## 8. 事件、风险和强勢入选

个股事件是辅助标签，不是入选条件。按以下规则计算可验证事件：

- 突破：P严格高于此前20个完成交易日的最高价，使用统一报价尺度；历史高价不足就不生成该事件。
- 再启动：上一完成日T≥65且当时处于上述整理判据；当前T≥65、R0>0、P≥当前MA5、P严格高于此前3个完成日最高价。直接标记，不增加采样等待。
- 反包：上一完成日收盘<开盘，当前R0>0且P≥上一完成日开盘。

事件可共存，主表最多展示两个，优先再启动、突破、反包。所有价位来源与日期保留在详情。板块只展示实际成员事件计数，如“突破3只、再启动2只”，不因为一个成员突破就声称板块整体突破。

当前焦点条件唯一为：

```
trend_strong = T非null且T≥65
emotion_strong = E非null且E≥65
focus = trend_strong OR emotion_strong
```

只用于当前有效行情/正式收盘结果；历史、午休、竞价参考必须以原时点标注，不冒充当前连续竞价结果。

禁止额外要求：今天正收益、三个周期同时强、完整多头、板块支持、低风险、未涨停、强度提升、多次采样、等待收盘、事件发生在限定窗口、环境必须回暖、资金为正、成交放量确认。

报价失效/无成交会使当前轴不可用；价格口径不明会使趋势轴不可用。这是数据问题，不是附加交易门槛。过热、冲高回落、涨停/跌停等已核验风险事实最多主表显示两个，其余折叠；不会再要求risk_clear才显示强度。

## 9. 输出契约、页面和排序

每只股票和每个board_catalog对象增加market_strength对象，至少包含：

```
version, trend_score, emotion_score,
trend_level, emotion_level, dominant_period,
phase, events, trend_strong, emotion_strong, focus,
trend_at, emotion_at, mode,
trend_parts_by_period, emotion_parts,
reasons, risks, data_reasons
```

趋势分项必须包含R/S/A/G/K/T、对应MA当前/前值、peak/dd/ATR及其日期；情绪分项包含R0/有效限制/S0/J/D/L/Oscore/H。板块另存expected、各趋势周期及情绪轴valid/coverage、成员代码、截尾代码、共振/强股比例。未知为null。

snapshot.market_strength保存规则版本、固定参数、实现哈希、统计时间、两轴参考池数量/哈希、两轴覆盖摘要、focus/trend/emotion完整ID列表和准确数量。不要在模型字段再建设pending/confirmed/limited/paused/event_rebuild等流程状态。

旧radar_opportunity/board_opportunity必要兼容字段只作新结果投影，不能重新评分或二次筛选。不把新模型作为孤立卡片，而让原雷达、板块筛选、成员列表继续读旧结论。

页面落实：

1. 雷达入口与板块/题材入口的“当前机会”改为“当前强势”，避免强弱评分被误读成买点承诺。
