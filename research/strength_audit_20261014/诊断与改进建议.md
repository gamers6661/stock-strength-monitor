# 趋势、情绪强度诊断及输入法修复

日期：2026-10-14。生产模型为 market-strength-2026-10-13.4。生产代码只修改 radar_ui.js 的搜索交互；两个现有渲染测试的最小DOM补充了事件注册接口。评分规则和参数未修改。证据来自当前源码、10:34扫描快照、固定输入复算及实际 HTTP 页面。

## 当前已经做到的事

趋势和情绪分别计算与排名；趋势以75%完成日历史力度、25%当前窗口力度为基础，有MA、ATR回撤、当前回落和短周期冲突折减。情绪分包含当日进攻、保持和近5日活跃度，保持分已经使用有效报价抽样。报价、完成交易日、价格口径和板块覆盖均有校验。不能继续沿用“没有历史趋势”或“只有当天涨幅”的旧诊断。

## 优先处理

### 1. 情绪总分允许承接转弱被历史活跃抵消

已复算的构造案例：近5个完成日每日涨3%，当天高开10%后回落至涨6%，现价恰在日内最低。保持分12.5，情绪总分仍为68.1，标签包括“情绪进攻”。原因是60%进攻+20%保持+20%近期活跃直接相加，保持差不能约束强势结论；现有风险主要提示相对昨收大跌和位置偏热，并不自动提示这种仍上涨的高开回吐。

这是公式边界证据，不是真实股票，也不是发生频率证据。10:34快照里没有情绪强且保持分低于35的股票。

建议：保留进攻力度，同时单列“进攻强、承接弱”，让高开回吐、日内低位及有效样本回撤能覆盖笼统的“情绪进攻”文字。是否折减分数或退出情绪强名单，要先冻结几类价格路径案例再定，不能直接把35当成生产阈值。保持良好的整理和极端弱承接应区别处理。

### 2. 新旧情绪判定共存

market_strength.py 用新模型分数判定情绪强；emotion.py 仍生成旧的活跃/前日涨停承接判定、角色和市场温度。快照中3040只有效情绪评分股票，有25只新旧 emotion_strong 不一致。例如皇台酒业旧值为真，新模型48.68分为假。当前主榜读取新模型，所以不能把25只全部称为页面错误。

旧市场温度按接近涨停价的比例容差计数，新模型按最小价位容差判定实际涨停，统计边界也不同。旧模块对同日报价的时段和新鲜度校验弱于新评分模块。

建议：强弱、角色与排序以新模型为唯一入口；旧模块保留可核验的昨天涨停股反馈等事实统计，并明确命名。市场温度与个股评分共享有效报价、涨停口径和统计分母，缺失值继续显示未知。

### 3. 趋势评分仍偏向端点涨幅，进攻形态只作标签

5/10/20日择最高基础分再折减；已经有短周期冲突惩罚，但短期分最高时，中期20/60日背景主要作说明。突破、再启动和反包不决定入榜，也没有量价确认。因此短期猛涨与中期趋势恢复可以同时被用户读成“趋势强”，轻微越过前高和有力度的突破也没有充分区别。

建议：保持上涨力度优先，把“短期进攻强、中期未恢复”“中期推进”“整理后再启动”作为可解释的结构状态；突破展示超过边界的幅度及ATR尺度，完成日成交量只能作为完成日量价依据。盘中没有可靠历史同时间成交量时，不计算或宣称同时间量比。先比较案例和排序关系，再决定结构状态是否影响分数。避免把所有股票都加上完整均线多头硬门槛，造成刚启动股票遗漏。

### 4. 板块均值不等于多数成员共同走强

板块趋势采用去极值收益和平均结构、平均回落，情绪采用整体进攻、情绪强股比例和保持中位数；这些已抑制单只极端股票，但仍会掩盖强弱分化。门槛是至少6只有效成员、至少80%覆盖；强股比例主要以有效样本计算，未知成员不等于弱股。

建议：在已有强股占比之外增加成员上涨占比、涨幅中位数、弱势占比及去掉前两名后的表现，显示有效数/应有数。先用这些证据区分少数领涨、普遍扩散和分化，不急于添加新的综合分。官方指数和主板成员结果继续分开，不推断谁带动谁。

### 5. 总览重复方向会放大共振印象

本轮目录有21组成分完全相同的方向，包括游戏/游戏Ⅱ、中药/中药Ⅱ等。它们确实是目录中的不同名称，不能直接改写同花顺分类；但总览连续展示同一批股票，容易被理解为多个独立方向一起变强。

建议：总览按相同成员归组展示，并保留原名入口；行业/题材目录和个股归属保持来源名称。相似但非相同的题材只能提示重合，不能擅自合并。

### 6. 分位、阈值和采样路径需要进一步验证

40%相对分位会随有效参考池和其他股票变化；现有转强观察已经用同一批可比成员，不能称其完全缺少可比控制，但仍应把绝对价格推进、分数变化和参考池变化区分展示。情绪过程只覆盖10—30分钟有效抽样，不足时取中性50，不代表真实中性，也不能证明连续封板、回封次数和封单质量。

65/80分界、三个周期收益尺度和各权重有工程测试；项目验收说明明确尚未完成跨行情阶段的收益验证。建议固定版本，对真实记录观察次日、3日、5日价格延续、回撤和相对主板表现，同时列出实际涨停导致不可成交、覆盖缺口与样本不足。板块历史采用当前成员重建，只能作为背景，不能称当时成分回测。工程测试通过不证明模型收益更好。

## 最小实施顺序

1. 统一情绪口径及统计分母；补充承接转弱的明确状态和风险覆盖。
2. 保留进攻力度，强化趋势结构状态与突破幅度证据。
3. 先增加板块分化证据、合并总览重复展示；不新增综合评分。
4. 冻结案例和版本，累积真实样本验证；证据支持后再改权重。

## 输入法修复及验收

原板块/题材搜索框每次input都调用msRender，整块innerHTML被替换，中文组词节点被销毁。原来的恢复焦点不保留输入法会话。

修复采用委托compositionstart/compositionend事件监听；组词和选词提交后的尾随input事件期间保持原节点，提交后才筛选。msRender同时避开正在组词的输入框，防止页面数据更新打断。代码/名称搜索框具有同一问题，已一起处理，并保留选区和焦点。

最终84项相关回归测试通过，check_dashboard.py通过。浏览器事件序列验证记录见 browser_ime_check.txt；它验证中文组词、连续提交、英文输入、方向筛选和清除，通过实际服务页面执行，UI版本为3919ae83e4379c930e018f57。搜索“电池”得到11个匹配方向，选择电池行业后趋势榜2只股票均满足成员筛选。该验证不覆盖 Windows 原生输入法候选窗的人工操作。

证据：audit_evidence.json、audit_strength.py、verify_ime.js、focused_tests.txt、dashboard_check.txt及baseline/radar_ui.js。
