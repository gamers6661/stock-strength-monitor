## 已确认并修复

| 问题 | 可能造成的影响 | 本轮处理 |
|---|---|---|
| 板块指数的逐个补核没有整轮时间上限 | 网络失败或缓存滞后时，补核拖住其他板块刷新 | 全池批量优先，批量45秒、整轮60秒；超时任务不等待，迟到结果不能写缓存；补核起点轮换，失败保留源时间与过期提示 |
| SQLite 上下文没有真正关闭连接，异常路径也有遗漏 | Windows文件占用、资源累积，正式Python运行环境测试失败 | 正常与异常路径显式关闭；事务提交和资源关闭分开处理；修正两处测试夹具自己的连接遗漏 |
| 半行JSONL追加读取时丢失先前记录或重复处理 | 历史观察参考不完整 | 只推进到完整行末，保留已完成记录，尾行补齐后读取一次 |
| 日线日期已最新，但完整性待核验状态没有优先重试；损坏状态可能阻断全池 | 已知修订未修复，或单股状态损坏拖垮刷新 | 独立校验状态，损坏记录重置并排入修复；超出本轮额度时保留待核验；受影响数据暂停新趋势与评分结论 |
| 较早的无来源记录触发不必要的全历史重抓 | 常规增量耗时增大 | 当前计算所需的最近61根用于口径检测；更早的未知来源保持未知，不补写来源。实际重叠价格或口径改变仍要求覆盖全部已有历史后替换 |
| 18点后的周期历史核验没有后台入口 | 最近20根之外的修订长期不能被发现 | 增加18点后分批核验，每批最多50个、采集预算60秒，与扫描共用锁；普通扫描不重复执行周期核验；核验必须覆盖已有历史。发现修订后同锁重算与发布 |
| 重算参考只认日期，历史数据或规则修订后仍沿用旧参考 | 分位、历史强弱比较依据过期 | 参考绑定原始输入与规则指纹，修订后重算；真实当日收盘留档保留当时事实，不反写 |
| 周更中途退出可能留下新旧混合的分类文件 | 成员、目录和归属版本冲突 | 分类事务写恢复记录；下次持有写锁时先恢复完整旧版本；损坏恢复记录明确报错，阻止继续写入 |
| 周更状态损坏或旧进程遗留“更新中” | 状态接口异常、页面长期显示更新中 | 验证状态字段并识别中断；保留七天更新周期 |
| 独立补日线、离线重放和发布入口不完全遵守共享约束 | 并发覆盖、重放丢失复权来源、发布失败却报告成功 | 补采共用写锁及完整性校验，离线读保留口径并关闭连接，重建检查实际页面发布结果 |
| 性能日志写失败影响已成功发布的状态 | 页面已更新却显示刷新失败 | 指标日志失败单独记录警告；真正的发布失败仍返回失败 |
| 轻量页面打包保留数字字典键，详情JSON转为字符串键 | 实时扫描发布后页面与详情一致性检查失败 | 统一JSON字典键语义，兼容旧打包记录；新扫描的内存参数、页面和详情使用同一传输表示 |

以上修改限定在数据有效性、恢复、资源和调度路径。已知口径异常暂停结论会影响受损股票的可用性，这是纠正错误判断；不通过放宽筛选条件解决缺失。
